ORBIT-2 · examples/sparse_reslim_forecasting

Forecasting 流水线：Sparse-Reslim 逐环节拆解

这份文档把 ORBIT-2 里的天气预报示例从磁盘上的 NPZ 文件一路讲到输出的预报场， 标出每一步的输入、输出和张量形状；最后用一节说明它和仓库主线的降尺度有什么不同、各自怎么跑。 文中所有形状都是在 Frontier 的 orbit 环境里实际跑出来的，不是推算的。

0它在仓库里的位置

ORBIT-2 主线做的是降尺度（把粗网格气候场变细），代码在 examples/intermediate_downscaling.py 加 src/climate_learn/models/hub/res_slimvit.py。 examples/sparse_reslim_forecasting/ 是另一条独立的线：确定性预报——网格分辨率不变，把时间往前推。

这个目录是有意做小的，只有两个文件：model.py（模型，只依赖 PyTorch）和 train.py（数据集 + 训练循环）。 它不走 FSDP、不走 TILES、不读 YAML 配置，默认单卡跑，目的是让人一眼看懂方法本身。 扩散生成（EDM）和论文规模的配置不在这里，在 完整的 Sparse-Reslim 仓库。

2数据侧：从 NPZ 到一个 batch

训练脚本读的是 ORBIT 一贯的按 split 分目录的 NPZ 布局。预报只需要一个目录， 因为输入和标签在同一张网格上，区别只在时间：

├── normalize_mean.npz   # 每个变量一个标量均值
├── normalize_std.npz    # 每个变量一个标量标准差
├── train/*.npz          # 每个文件一段时间，键是变量名
├── val/*.npz
└── test/*.npz
D1

读盘并统一布局

输入NPZ[var] = [Ttotal, H, W] 或[Ttotal, 1, H, W] → 输出[Ttotal, H, W]

多出来的长度为 1 的那一维会被压掉；其他维数直接报错，不猜。

train.py · _as_time_lat_lon()

D2

逐变量标准化

输入[Ttotal, H, W] → 输出[Ttotal, H, W]

(x − mean[var]) / std[var]，每个变量一个标量。标准差为 0 会直接抛错。 注意标签也被同一组常数标准化了，所以后面的 loss 是归一化空间里的数，不是物理单位。

train.py · _load_normalization() / ERA5ForecastDataset.__iter__()

D3

切出一个「输入历史 → 未来标签」样本对

输出 · 输入端[T, V, H, W] 输出 · 标签端[Vout, H, W]

时间索引规则：合法起点是 t ∈ [(T−1)·window, Ttotal − pred_range)。 输入取 t, t−window, …, t−(T−1)·window（按时间正序排好），标签取单帧 t + pred_range。 这是直接预报——一次跳到目标时刻，不做自回归滚动。

train.py · ERA5ForecastDataset（IterableDataset，多 worker 时按文件切分）

D4

DataLoader 组 batch

输出 · 输入端[B, T, V, H, W] 实测(2, 1, 2, 128, 256)
输出 · 标签端[B, Vout, H, W] 实测(2, 2, 128, 256)

这就是喂给模型的东西。模型也接受省掉时间维的 [B, V, H, W]，内部会自动补上 T=1。

3模型侧：14 步形状流

橙色标出的三步是 Sparse-Reslim 的核心，其余部分是一个常规的变量聚合 ViT。

编码：把气象场变成 token
1

输入

[B, T, V, H, W] 实测(2, 1, 2, 128, 256)

模型会校验 T、V、(H,W) 三项是否和构造时一致，对不上直接报错。

2

逐变量 patch 嵌入

输入[B, T, H, W]（每个变量一份） → [B, D, H/p, W/p] → [B, L, D]

每个变量有自己独立的 Conv2d(T → D, kernel=stride=p)：卷积核等于步长，等价于不重叠地切块再线性投影。 历史帧放在通道维里，所以一次卷积就把时间吃掉了。展平后 L = (H/p)·(W/p)。

实测：(2,1,128,256) → (2,128,64,128) → (2,8192,128)，L = 8192

3

堆叠变量 + 变量身份嵌入

输入V × [B, L, D] → [B, L, V, D] 加上variable_embed [1, 1, V, D]

同一个格点上的各个变量被排在一起；可学习的 variable_embed 告诉模型「这一条是哪个变量」。

实测：(2, 8192, 2, 128)

4

变量聚合：把 V 个变量压成 1 个 token

输入[B·L, V, D] query[B·L, 1, D] → [B, L, D]

一个可学习的 variable_query 对该格点的 V 个变量做交叉注意力，得到一个融合 token。 关键点：注意力只在变量维上做（长度 V，很短），B·L 全被当成 batch。 好处是变量数可以变，L 不随变量数增长。

实测：(16384, 2, 128) → (2, 8192, 128)

5

加位置嵌入

[B, L, D]+position_embed [1, L, D] → [B, L, D]

可学习参数，形状在建模型时就按 L 定死了——换网格尺寸就得重新训， 不像降尺度那边会在线插值（见第 6 节）。

路由：dense → sparse → dense
6

前段稠密块 ×num_dense_early

[B, L, D]→[B, L, D]

标准 pre-norm Transformer 编码层（GELU，mlp_ratio=4）。默认只有 1 层，让全部 token 先互相看一眼。

7

采样 token 子集（无参数路由）

输入[B, L, D] → 索引[B, L·r] → gather[B, L·r, D]

做法是 torch.rand(B, L).topk(L·r)——本质是每个样本独立随机抽一批空间位置， 抽完按索引排序以保持原有顺序。没有任何可学习参数，也不看 token 内容。 保留数是 max(1, int(L · keep_ratio))。

实测：8192 → 2048（25%）

8

中段稀疏块 ×num_sparse_middle

[B, L·r, D]→[B, L·r, D]

默认 4 层，只在这 25% 的 token 上跑。序列短了 4 倍，自注意力这一项就省了 16 倍。

9

散射回稠密网格（残差形式）

delta[B, L, D] = scatter(稀疏输出 − 稀疏输入) → [B, L, D]

写回的是增量而不是替换值：被跳过的 token 拿到 0，因此原样保留在恒等路径上。 这正是名字里 "Reslim" 的来历——稀疏块只负责修正，不负责重建。

10

后段稠密块 ×num_dense_late + LayerNorm

[B, L, D]→[B, L, D]

num_dense_late = depth − num_dense_early − num_sparse_middle，默认 6 − 1 − 4 = 1。 这一层让被修正过的 token 和被跳过的 token 重新混合，避免残留拼接痕迹。

解码：token 变回气象场
11

解码头

[B, L, D]→[B, L, Vout·p²]

单层 Linear，把每个 token 展开成它那一小块 patch 上所有输出变量的像素。

实测：(2, 8192, 8)，即 2 变量 × 2 × 2

12

Unpatchify：拼回二维场

[B, L, Vout·p²]→[B, Vout, H, W]

reshape 成 [B, H/p, W/p, Vout, p, p]，换轴再合并。 分辨率进出相同——这是预报和降尺度最直观的区别。

实测：(2, 8192, 8) → (2, 2, 128, 256)

13

并行卷积残差支路

输入x[:, −1, out_idx] = [B, Vout, H, W] → [B, Vout, H, W]

取最后一帧历史场里的输出变量，过 Conv3×3 → GELU → Conv3×3（隐藏宽度 max(16, D/4)）。 这条支路只做局部持续性修正，和 Transformer 支路并行，不共享权重。 也正因为它要从输入里按名字取输出变量，输出变量必须是输入变量的子集，否则构造模型时就报错。

14

相加得到预报

第 12 步+第 13 步 → [B, Vout, H, W] 实测(2, 2, 128, 256)

和标签形状完全对齐，直接算 MSE。

4稀疏路由省在哪里

自注意力的开销随序列长度平方增长，所以把中间几层的 token 砍到四分之一，省下的远不止四分之一。 下面按默认配置（L=8192，depth=6，1 dense → 4 sparse → 1 dense，r=0.25）把注意力矩阵的规模算出来。

一个需要知道的性质：这段路由代码没有区分训练和推理——torch.rand 在 model.eval() 下照样生效。 也就是说同一份输入跑两次，结果会略有不同。想要确定性输出，需要固定随机种子，或者自行改成 eval 时走全稠密路径（把 keep_ratio 设成 1.0 即可绕过采样）。

5训练回路

模型外面包了一层很薄的 pl.LightningModule，没有自定义调度或分布式逻辑：

环节内容
损失F.mse_loss(forecast, target)，train / val / test 三个阶段共用同一个函数，记为 {stage}/mse。是归一化空间里的 MSE，不是 K 或 mm。
优化器AdamW，lr=5e-4、weight_decay=1e-5，无学习率调度
检查点ModelCheckpoint 监控 val/mse，只留最好的一个，存到 <output-dir>/checkpoints/
早停EarlyStopping，--patience 默认 5；设成 0 可关掉
设备--accelerator / --devices，默认 auto + 1 张卡
收尾trainer.test(..., ckpt_path="best")——训完自动用最好的检查点在 test split 上跑一遍

数据集是 IterableDataset，多 worker 时按文件切分（files[worker.id::num_workers]）， 所以 --num-workers 最好不要超过该 split 的 NPZ 文件数，否则会有 worker 空转。

6Downscaling 与 Forecasting：差在哪，各自怎么用

两者共用同一套直觉——逐变量 patch 嵌入、可学习 query 做变量聚合、Transformer 主干旁挂一条卷积残差支路—— 但解决的是两个不同的问题，代码路径也是分开的。

任务本身的区别

降尺度回答「同一时刻，这块粗网格细看是什么样」：输入输出时间相同、分辨率不同， 训练要成对的低分辨率 / 高分辨率数据。 预报回答「同一块网格，若干小时之后是什么样」：输入输出分辨率相同、时间不同， 训练只需要一条时间序列。

Downscaling

Res_Slim_ViT · 主线

  1. 低分辨率场 [B, T, Cin, H, W]，时间维展平进通道
  2. 逐变量 PatchEmbed + 变量聚合 [B, L, D]
  3. 加插值后的 sincos 位置嵌入，再加一个空间分辨率嵌入
  4. depth 层全稠密 Transformer（可选 TILES 分块）
  5. 解码头输出 [B, L, Cout·(mag·p)²]
  6. Unpatchify 带放大 → [B, Cout, H·mag, W·mag]
  7. 残差支路：PixelShuffle 上采样卷积，同样放大 mag 倍
  8. 两路相加（尺寸不齐时裁剪对齐）

Forecasting

SparseReslim · 示例

  1. 历史场 [B, T, V, H, W]，时间维进 conv 的通道
  2. 逐变量 Conv2d + 变量聚合 [B, L, D]
  3. 加可学习位置嵌入（无分辨率嵌入）
  4. 1 稠密 → 4 稀疏 → 1 稠密，中段只走 25% token
  5. 解码头输出 [B, L, Vout·p²]
  6. Unpatchify 不放大 → [B, Vout, H, W]
  7. 残差支路：同分辨率卷积，输入是最后一帧
  8. 两路相加（尺寸天然一致）

怎么跑 · Forecasting

先用合成张量跑一遍冒烟测试，不需要任何数据，同时验证前向和反向：

python examples/sparse_reslim_forecasting/train.py --smoke-test

# Smoke test passed: forecast=(2, 1, 8, 16), sparse_tokens=8/32, loss=1.6330

有数据之后，在仓库根目录下：

# 单变量、提前 6 个存储步长的默认设置
bash examples/sparse_reslim_forecasting/launch.sh /path/to/ERA5_DIR \
  --max-epochs 30 --batch-size 16 --pred-range 6

# 多变量：输出变量必须同时出现在输入里
bash examples/sparse_reslim_forecasting/launch.sh /path/to/ERA5_DIR \
  --input-vars 2m_temperature 10m_u_component_of_wind \
  --output-vars 2m_temperature 10m_u_component_of_wind

# 先拿几个 batch 跑通端到端再说
python examples/sparse_reslim_forecasting/train.py /path/to/ERA5_DIR \
  --limit-train-batches 4 --max-epochs 1 --accelerator cpu

常用开关：--history、--window、--pred-range 控时间； --keep-ratio、--num-dense-early、--num-sparse-middle 控稀疏路由； --patch-size、--embed-dim、--depth、--num-heads 控模型大小； --output-dir 指定日志和检查点位置。

怎么跑 · Downscaling

降尺度不吃命令行参数，一切都在 YAML 里。Frontier 上：

# 1. 选一个配置：interm_8m / interm_117m / interm_1b / interm_10b
# 2. 确认 fsdp × simple_ddp × tensor_par == 总 GPU 数
# 3. 改 launch_intermediate.sh 里的 -A 账号、conda 路径、配置文件名
cd examples/
sbatch launch_intermediate.sh
tail -f flash-{JOBID}.out

# 训完出图
sbatch launch_visualize.sh

单机多卡（如 DGX）把配置里 gpu_type 设成 nvidia，然后：

mpirun -n [NUM_GPUS] python -u intermediate_downscaling.py [CONFIG_FILE] MPI

几个已知的坑： 所有 HuggingFace 权重的 decoder_depth 都是 4，配置里写 2 会形状不匹配、加载失败； 开 TILES 时瓦片尺寸必须能被 patch_size 整除，不行就调 overlap； 由于气候数据经纬 2:1 的长宽比，实际横向 overlap 是纵向的两倍； 美国区域权重和全球权重的 pos_embed 分别是 7200 和 16928 个 token，不能互换。

该用哪一个

  • 手上是配好对的粗 / 细分辨率数据，想要更细的场 → 降尺度。有预训练权重可以微调，规模也能拉到多节点。
  • 手上是单一网格上的时间序列，想往后推 → 预报。从头训，单卡起步。
  • 想把预报做到论文规模 → 这个示例只是入门；完整实现在 Sparse-Reslim 仓库，含 EDM 扩散生成和分布式训练。
